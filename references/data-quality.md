# 数据质量校验清单 · Data Quality

本文件供 `qianjin-data-analysis` 在 Step 2 执行。分析前必跑，避免"垃圾进垃圾出"。逐项排查，结果写入报告附录。

---

## 一、基础完整性

- [ ] **缺失值**：各列缺失比例，关键列（金额/时间/ID）缺失须处理或标注
- [ ] **重复行**：按主键（order_id / user_id + 时间）去重，记录删除数
- [ ] **空行/脏行**：分隔符错位、表头错位、汇总行混入
- [ ] **编码**：中文乱码、BOM、全半角混用

## 二、类型与口径

- [ ] **时间列**：能否解析为日期；时区、格式统一（YYYY-MM-DD）
- [ ] **金额列**：单位一致（元/万元）；是否有负数、0、异常大值
- [ ] **分类列**：同义不同写（"iPhone"/"iphone"/"苹果手机"）需归一
- [ ] **ID 列**：是否存在空 ID、测试账号、内部账号

## 三、分布与合理性

- [ ] **数值范围**：是否超出业务可能（如年龄 200、金额 1e9）
- [ ] **时间连续性**：是否有断档（某天/某月无数据）
- [ ] **极值**：Top/Bottom 5 抽样核对，确认非录入错误
- [ ] **逻辑矛盾**：退款额 > 销售额、下单时间 > 支付时间等

## 四、关联与口径确认

- [ ] **多表关联**：主键能否 join；一对多是否需聚合
- [ ] **统计口径**：GMV 是否含未支付、退款；"活跃"定义
- [ ] **时间窗**：用户分析的"周期"是否统一（月/季）

## 五、输出要求

- 发现的每个问题记录：问题 / 影响范围 / 处理动作（删除/填充/标注）
- 明确列出"因数据不足无法支持的结论"，不强行分析
- 口径假设在报告附录显式声明，避免误读

> 可用 `scripts/analyze_data.py` 自动产出基础画像（缺失/类型/分布），人工仅做业务判断层校验。
